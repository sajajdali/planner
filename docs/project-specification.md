طراحی و پیاده‌سازی سیستم برنامه‌ریزی روزانه و مدیریت وظایف

یک سیستم کامل برنامه‌ریزی روزانه و مدیریت وظایف طراحی و پیاده‌سازی کن.

تکنولوژی‌های اصلی

Backend

* Laravel
* REST API
* MySQL
* Laravel Sanctum برای احراز هویت
* استفاده از Service Layer و Repository Pattern در بخش‌های لازم
* استفاده از Form Request برای اعتبارسنجی
* استفاده از API Resource برای خروجی API
* استفاده از Queue برای اعلان‌ها و پردازش‌های زمان‌بر
* استفاده از Scheduler برای یادآوری‌ها و تسک‌های زمان‌بندی‌شده

Frontend

* Vue.js 3
* Composition API
* TypeScript
* Pinia برای مدیریت State
* Vue Router
* Axios
* طراحی Responsive برای دسکتاپ، تبلت و موبایل
* رابط کاربری فارسی و راست‌چین
* پشتیبانی کامل از RTL
* امکان استفاده به‌صورت PWA در مراحل بعدی

⸻

هدف اصلی سیستم

کاربر باید بتواند برای هر روز برنامه مشخصی ایجاد کند، وظایف خود را در دسته‌بندی‌های مختلف قرار دهد، برای هر وظیفه زمان تعیین کند، وظیفه را به زیروظیفه تقسیم کند، زمان واقعی انجام آن را با دکمه شروع و پایان ثبت کند و در پایان روز گزارش کاملی از عملکرد خود ببیند.

سیستم باید ساده، سریع، حرفه‌ای، انگیزه‌بخش و مناسب استفاده روزانه باشد.

رفتار تکمیل وظیفه

در کنار هر وظیفه یک Checkbox یا دکمه تیک قرار بگیرد.

* وضعیت وظیفه به «انجام‌شده» تغییر کند.

این رفتار باید از تنظیمات قابل مدیریت باشد.

* هر زیروظیفه را جداگانه تیک بزند.

ساختار دیتابیس بهتر است امکان زیروظیفه چندسطحی را داشته باشد، اما در رابط کاربری نسخه اول فقط یک سطح زیروظیفه نمایش داده شود.

سیستم تایمر

هر وظیفه و زیروظیفه باید قابلیت ثبت زمان داشته باشد.

روی هر وظیفه دکمه‌های زیر وجود داشته باشد:

* شروع
* توقف موقت
* ادامه
* پایان

با زدن دکمه شروع:

* وضعیت وظیفه به «در حال انجام» تغییر کند.
* زمان شروع ثبت شود.
* تایمر به‌صورت زنده نمایش داده شود.
* در بالای صفحه وظیفه فعال نمایش داده شود.
* اطلاعات تایمر حتی با Refresh صفحه از بین نرود.

با زدن توقف موقت:

* Session جاری متوقف شود.
* مدت زمان تا آن لحظه ذخیره شود.
* کاربر بتواند بعداً ادامه دهد.

با زدن پایان:

* زمان پایان ثبت شود.
* مدت زمان واقعی محاسبه شود.
* کاربر انتخاب کند که وظیفه تکمیل شده است یا فقط تایمر متوقف شود.

یک وظیفه ممکن است در چند نوبت انجام شود؛ بنابراین برای هر بار شروع و توقف باید یک Time Session جدا ذخیره شود.

برای مثال:

وظیفه: توسعه صفحه ورود

* جلسه اول: ۰۹:۰۰ تا ۰۹:۴۵
* جلسه دوم: ۱۰:۱۵ تا ۱۱:۰۰
* جلسه سوم: ۱۴:۰۰ تا ۱۴:۳۰

مجموع زمان واقعی: ۲ ساعت

سیستم در نسخه اولیه اجازه دهد فقط یک تایمر هم‌زمان فعال باشد.

اگر کاربر هنگام وجود یک تایمر فعال، تایمر دیگری را شروع کرد، یک Modal نمایش داده شود:

«تایمر وظیفه دیگری در حال اجراست. ابتدا آن را متوقف کنید یا تایمر فعلی را متوقف و تایمر جدید را آغاز کنید.»

وظایف بدون تایمر

همه وظایف الزاماً نیاز به تایمر ندارند.

کاربر باید بتواند:

* فقط وظیفه را تیک بزند.
* برای وظیفه ساعت برنامه‌ریزی تعیین کند، ولی تایمر اجرا نکند.
* مدت زمان واقعی را به‌صورت دستی وارد کند.
* هیچ زمانی برای وظیفه تعیین نکند.

برای مثال:

* خوردن مکمل
* نوشیدن آب
* خرید روزانه
* تماس با شخص خاص
* ثبت وزن

کاربر بتواند بین این حالت‌ها جابه‌جا شود:

* نمایش بر اساس دسته‌بندی
* نمایش لیستی
* نمایش Timeline
* نمایش فقط وظایف باقی‌مانده

* لغو وظیفه
